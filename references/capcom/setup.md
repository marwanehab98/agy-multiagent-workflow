# Capsule Communicator: Setup

Part of mission-control. The Rules in `<SKILL_DIR>/skills/mission/SKILL.md` (or `<SKILL_DIR>/SKILL.md` in a flat install) hold here. Run this before Step 1 of a new run: it settles the run's three picks. `SKILL_DIR`, `CFG` (`$HOME/.config/mission-control`) and `CATALOG` (`<CFG>/catalog.json`) are as that skill defines them.

1. **Detect:** run `mkdir -p <CFG>`, then `python3 -I <SKILL_DIR>/scripts/harnesses.py detect --out <CATALOG>`.
2. **Remembered picks:** if the user's request names a pick for all three roles, skip this item and go to item 3: the picks they named come before the ones remembered. Otherwise run `python3 -I <SKILL_DIR>/scripts/roles.py remembered --roles <CFG>/roles.json --catalog <CATALOG>`.
   - **Menu lines** (item 3 describes them): the last selections this session can still use, newest first, then `new`. Ask "Which picks?" as in "Asking" below. A selection's value is its three picks, `director=<pair> safety=<pair> crew=<pair>`: go to item 4 with them. `new` goes to item 3. Never offer, rebuild or alter a selection yourself, however close a model looks or whatever the user delegates to you: only a row the user picks counts.
   - **`NONE`:** if the user asked for the picks of an earlier run, say exactly "None of your saved selections can be used in this session, so pick each role." Then go to item 3.
3. **Ask the three roles,** in this order: Flight Director (`director`), Range Safety (`safety`), Crew (`crew`). For each, ask three questions in turn, as in "Asking" below. `MENU` means `python3 -I <SKILL_DIR>/scripts/roles.py menu --catalog <CATALOG>`:
   1. harness: `MENU` (if a `roles.py` command prints `UNKNOWN session ?`, run it, and every later `roles.py` and `switch.py apply` command, with `--session-harness <the harness you run in>`);
   2. model: `MENU --harness <harness>`;
   3. effort: `MENU --harness <harness> --model <model>`.

   Each menu line is `N<TAB>value<TAB>label`, and some lines end with `<TAB>subtitle`; show any `BROKEN` and `LOCKED` lines exactly before the question. A `LOCKED` line means a harness is signed in with OAuth, so the menu lists only this session's harness. The question is "<role>: which <harness|model|effort>?", and the rows are its options, labelled with each row's label, with its subtitle (when it has one) as the option's description and never in the label, in menu order. A menu with exactly one row isn't asked: take that row and say "<role> <harness|model|effort>: <label>, the only option." The pick is `<harness>:<model>@<effort>`, using each chosen row's value. When asking for `crew`, note that its `<model>@<effort>` must differ from the `director` pick so escalation has a higher rung. If the user's opening prompt already named explicit model/effort picks that unambiguously match detected menu rows for all three roles, don't ask the 9 separate questions: show those matched `role=pair` lines in one block, then ask "Use these picks?" as in "Asking" below, with the options `same` and `new`. This is a fixed prompt. "same" goes to item 4 with those picks; "new" asks the three roles as above. Never invent or substitute a row the user didn't name.

   **Asking.** With a multiple-choice question tool (such as `ask_question` / `AskUserQuestion`), ask with it: no option marked recommended, and the options set by the number of rows (not counting the free-text choice the tool adds):
   - **2–4 rows:** one question, one option per row. Never a `More` option.
   - **5 or more rows:** pages. The first page is rows 1–3 plus an option `More`, which asks again with the remaining rows the same way, until 4 or fewer remain; those form the last page.

   Without such a tool, write the question, then one line per row, `N. label`, with a row's subtitle on an indented line of its own under it. The answer is the row the user selected, or a typed reply that is exactly a row's number, value or label; anything else, including free text that names no row or names something the menu does not list (a harness left out by a `LOCKED` line, a model the catalog lacks), gets exactly "Pick one of the listed options." and the same question again.
4. **Check the picks:** run `python3 -I <SKILL_DIR>/scripts/roles.py check --catalog <CATALOG> --jira <yes if the request has a JIRA key, else no> --director <pair> --safety <pair> --crew <pair>`.
   - **Exit 0:** show any `NOTE` line exactly, and go on.
   - **Exit 1 with any `MISSING` line:** show every `MISSING` and `UNKNOWN` line exactly, then say exactly "The run can't start until these are fixed. Install what's missing, or choose different picks, then ask me again." Then stop: don't save, and don't start Step 1 (Rule 21).
   - **Exit 1 with only `UNKNOWN` lines:** show them exactly with a one-line plain-English explanation (e.g. `crew` cannot match the `director` pick, or every role must be on this session's harness while a harness is signed in with OAuth), ask each named role again as in item 3, and repeat this item.
5. **Save:** run `python3 -I <SKILL_DIR>/scripts/roles.py save --roles <CFG>/roles.json --director <pair> --safety <pair> --crew <pair>`.
6. **Begin coordination in this session:** read `<SKILL_DIR>/references/capsule-communicator.md` in full, then `<SKILL_DIR>/references/capcom/step-1-intake.md`, and execute from Step 1, reading each later step's file as you reach it, using `ROLES_FILE=<CFG>/roles.json`, `SETUP_CATALOG=<CATALOG>`, and the user's original request verbatim.
